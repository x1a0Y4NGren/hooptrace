## 执行顺序

1. 核对候选 `codex/hooptrace-v2`、main 用户改动及远端分支，保留原始证据。
2. 复核 200% 英文目标分提示被裁剪的问题，先补生产字体回归，再做最小布局修复；保持版本 `2.0.0+4`、schema 3、JSON 2。
3. 更新双语变更记录、元数据、安装说明及实际截图来源，执行适用验证。源码变化后取得同一最终输入的五项 CI 成功记录。
4. 验证新密钥的可跨电脑恢复备份，按维护者 2026-10-08 的选择保存本机与一份 U 盘副本，并独立保存恢复口令；不称为两份离线副本。
5. 从干净的 main 发行检查点构建正式 APK，核验证书、版本、权限、三 ABI 及 SHA-256；在专用合成设备复验受影响界面和正式包启动。
6. 确认全部适用门槛后创建唯一签名 tag、发布 APK 和校验和；从公开渠道回读 APK、核验签名并安装冒烟，归档实际结果。

不在带用户未提交改动的 main 检出中合并或构建。main 的 AOCI 索引绑定该检出的 1.1 源码，不能据此声明已读取候选的全部实现；本轮候选变更按对应源码与测试验证。

## 目标分提示修复与本地验证

应用源码 `c99a4436007203e5b4a5f07b632c5f274ed100b8` 仅调整目标分弹窗边距到 16dp。旧弹窗在窄屏、大字和键盘同时存在时，标题与按钮换行挤压滚动区；提示文字仍在树中但范围不可见，单纯无异常断言未覆盖这个问题。真实字体测试先失败，再验证整段辅助及错误说明在可见区域内，输入与至少 48dp 的取消／确认仍可用，不减小系统文字缩放。
